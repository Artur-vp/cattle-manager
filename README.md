# CATTLE MANAGER
#### Video Demo:  https://youtu.be/-ft2oCgLpik
#### Description:

Cattle Manager is a web application built with Flask (Python) and SQLite3, designed to help farmers and ranchers digitally manage their livestock. The project replaces traditional paper records and spreadsheets with a fast, secure, and accessible tool available from any device with a browser. The application uses CS50's library for database interaction, Jinja2 for HTML templating, and Bootstrap combined with a custom farm-themed design for the interface.

Authentication:
The application starts with a user authentication system. Users can register an account with a username, password, and password confirmation, and log in to access their personal dashboard. Every route in the system is protected by the @login_required decorator, which redirects unauthenticated users to the login page. The session["user_id"] variable is used throughout the application to ensure that each user only sees and manages their own data — never another user's animals. The login and register pages follow the same farm-themed visual identity as the rest of the application, with green tones, rounded cards, and clean typography.

New Animal:
The New Animal page allows users to register a new animal into the system. The registration form collects four pieces of information: the animal's identification name, date of birth, price, and sex (Female or Male). Before inserting the record, the backend validates all fields — checking that the identification is not empty, that the birth date was provided, that the price is a positive number, and that the animal's name does not already exist in the user's catalog. This last check prevents duplicate entries by querying the database before inserting. Once registered, the animal is saved in the animais table with a criado_em timestamp that records exactly when it was added. Below the form, a permanent register history table displays all animals added by the user, showing the identification and the registration date. This history persists across sessions since it is always fetched from the database.

Catalog:
The Catalog page is the main view of the application. It displays a complete table of all animals registered by the logged-in user, showing the identification, sex, date of birth, automatically calculated age, and price. The age calculation is done in Python using the datetime module — it computes the exact difference in years and months between the animal's birth date and today's date, correctly handling cases where the birthday has not yet occurred in the current month. The page also displays a total herd value at the bottom, calculated using a Python generator expression that sums the valor field of all animals. A search bar powered by JavaScript allows users to filter animals by name in real time, instantly hiding rows that do not match the typed term without any server request. The Remove button on each row redirects the user to the History page to register the reason for removal before the animal is deleted.

Control:
The Control page gives the farmer a quick statistical overview of their herd. It displays three metric cards showing the total number of animals, the number of females, and the number of males. These values are calculated in Python using generator expressions that count animals by their sex field. Below the cards, a pie chart built with Chart.js visually represents the distribution between males and females, using pink for females and blue for males. The chart is responsive and adapts to the size of its container, giving the farmer an immediate visual summary of their herd composition.

History — Removal Control:
The History page handles the removal of animals from the herd. It contains a form with two fields: a searchable dropdown listing all current animals — powered by Choices.js with exact-match search — and a reason selector with three options: Sold, Death, or Disappeared. When the form is submitted, the backend first validates both fields, then inserts a record into the removals table containing the animal's name, the reason, and the removal timestamp. After that, it executes a DELETE query on the animais table to remove the animal from the catalog. Below the form, a permanent removal history table displays all past removals with color-coded badges for each reason — green for Sold, red for Death, and amber for Disappeared — making it easy to read at a glance. Users can also clear the entire removal history with a single button, which executes a DELETE on the removals table without affecting the animals still in the catalog.

Design:
The entire application follows a consistent farm theme with a dark green navbar (#3B6D11), light green accents (#EAF3DE, #C0DD97), white cards with subtle green borders, and warm beige backgrounds (#f5f0e8). Error pages display a friendly apology card with a go-back button. Every page — login, register, catalog, history, control, and new animal — shares the same visual language defined in the layout.html base template, ensuring a cohesive and professional experience throughout the application.
